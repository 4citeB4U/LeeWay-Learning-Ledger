# LeeWay Ordered Learning — Authority, Permission, Practice and Admission Contract

**Status: SOURCE REVIEW.** Applies to every registered permanent LeeWay worker and authorized outside LLM teaching lane; the **original** Standards, Machine Consciousness, Runtime, Agent Skills, Workforce, Veritas, Receipt, Continuum and Learning authorities remain independent. This is an interface/acceptance contract, **not** a second experience ledger, credential issuer, training job queue, neural trainer, badge issuer, production Veritas writer or Formula engine.

## What “learning” means — five differentiated outputs

| Type | Valid observation | Permitted result | Forbidden promotion |
| --- | --- | --- | --- |
| **Information acquisition** | Authorized source read, teacher explanation | Ephemeral comprehension and source-linked notes | No claim of model-weight retraining, permanent memory or permission |
| **Skill practice** | Authorized bounded learner exercise and measured feedback | Temporary candidate skill/behavior with failures and corrections | No real-world actuation beyond granted task; no self-issued qualification |
| **Generalization** | Different, withheld/held-out case independently completed | Evaluated ability to select tools, make decisions, recover and explain | No claim from memorized answer, same fixture or teacher prompting |
| **Institutional learning** | Independently verified execution and eligible canonical receipt/readback | Authorized Learning Ledger admission, versioned skill/procedure when approved | No new role, identity, grant, verifier or private-data retention |
| **Model-weight training** | Owner-approved licensed data, qualified compute/model train run, measured baseline/post and reproducible checkpoint | Explicitly qualified model artifact via original Model Hub / Formula / Veritas gates | Never infer weight change from conversation, feedback, prompt or source edit |

**A lesson can be studied without being applied; practiced without being permanent; verified without being generally authorized; and admitted without being deployed.** Outcomes must identify which of these actually happened.

**Stage progression:** LG-00 → LG-01 → LG-02 → LG-03 → LG-04 → (LG-05 where real practice requires actuation) → LG-06 → LG-07 → LG-08 → LG-09 → LG-10. A blocked real-execution gate does not bar lawful source study or simulated practice; it **does** bar claims of physical/prod competence. Omitted gates require authorized N/A reasons and must never omit an applicable hard gate.

## Permission types (not interchangeable)
- `LEARN_READ`: inspect approved standards and teaching materials.
- `LEARN_CAPTURE`: collect minimum authorized observation or feedback (requires source/data-owner consent).
- `LEARN_PRACTICE_SANDBOX`: bounded practice without real privileged device effects.
- `LEARN_PRACTICE_LIVE`: exact action under existing Runtime/Device Bridge and OS/user approval, never an implicit blanket privilege.
- `LEARN_EVALUATE`: independent reviewer evaluates; cannot be the learner/teacher for that exact decision.
- `LEARN_PROPOSE_ADMISSION`: submit an eligible learning candidate but not issue acceptance.
- `LEARN_ADMIT_CANONICAL`: original canonical writer and independent verifier only.
- `LEARN_RELEASE_SKILL`: independent source/release/role owner approval; does not grant new operating-system rights.
- `LEARN_REVOKE_OR_CORRECT`: original owning permission/privacy/learning authorities record correction; preserve old evidence with explicit supersession.

## Critical counterfactual and refusal tests
- Teacher says “I taught you,” but learner only repeats the same example: `NOT_GENERALIZED`; mentor evidence remains incomplete.
- Outside model invents a new policy and self-assigns `LEARN_ADMIT_CANONICAL`: `BLOCKED_AUTHORITY`.
- Worker has `LEARN_READ` but attempts to operate phone camera: `BLOCKED_SCOPE`; reading permission does not become OS consent.
- Practice result improves locally but lacks independent Veritas/receipt/readback: `CANDIDATE_ONLY`, not production learning.
- Candidate lesson captures user conversations with no informed capture consent: `BLOCKED_PRIVACY`, delete/quarantine per original owner rules.
- New skill passes but degrades after update: apply LG-10, stop use where required, preserve original evidence, rollback and reassess.
- Worker teaching and evaluation performed by same external LLM: cannot earn independent teach-back badge.
- Device-specific Brain or Diagnostics “learning” migrated into global Ledger as shared device ownership: `BLOCKED_DEVICE_SOVEREIGNTY`; only permitted sanitized cross-device methods may be candidates.
- Verified lesson improves technique but no role grant exists: keep admission and deployment separate; `BLOCKED_SKILL_RELEASE`.
- Human withdraws learning capture consent: stop future capture/use as required, follow applicable retention/deletion rules, do not rewrite immutable execution receipts.
