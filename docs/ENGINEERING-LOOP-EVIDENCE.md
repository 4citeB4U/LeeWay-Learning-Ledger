# Evidence before promotion — engineering loop learning protocol

**Authority:** [LeeWay Canonical Engineering Laws](https://github.com/4citeB4U/LeeWay-Standards/blob/main/Docs/governance/LEEWAY-CANONICAL-ENGINEERING-LAWS.md) (especially 01, 03–05, 07, 09, 11, 12), [R01–R25](https://github.com/4citeB4U/LeeWay-Standards/blob/main/standards/PERMANENT-ENGINEERING-RULES.md), [Agent Operating Loop](https://github.com/4citeB4U/LeeWay-Agent-Skills/blob/main/skills/leeway-agent-operating-loop/SKILL.md), [Contributor Handoff](https://github.com/4citeB4U/LeeWay-Agent-Skills/blob/main/docs/CONTRIBUTOR-HANDOFF-PROTOCOL.md), and the existing post-receipt Learning Ledger skill. This is an implementation aid, **not a new Veritas or knowledge authority**.

## Non-negotiable engineering stages

`Investigate → Diagnose → Plan → Implement → Test → Validate → Repair → Retest → Verify → Evidence`.

For every stage, preserve its actual finding/decision, source/issue/receipt references, and current evidence classification. Do not omit Repair/Retest because a first test happened to pass: document the actual repair and retest when one occurred, or record those stages as not applicable/not executed with the justified boundary; do **not** assert false execution. The source checkpoint below documents a real pre-existing hardening repair and its retest.

For a substantive task, contributor notes belong to the **owning issue/PR** at BEGIN, DURING, PROBLEM, RESOLUTION, and END. This compact checkpoint is an *index and reconstruction record*; original CI logs, commits, protected runtime receipts and owner local state remain in their actual authorities. All references remain reviewable without copying private user or device data into a public repository.

Green CI demonstrates the gate ran on that PR source, not that all external evidence is true.

## Promotion and knowledge reuse

1. **SOURCE_EVIDENCED:** Preserve a correctly documented engineering arc and source checks. A failure remains valuable even if the production mission is unfinished.
2. **CANDIDATE_RETRIEVAL:** `projectEngineeringLesson` makes the *nonpersonal source-level hypothesis* discoverable to approved Agent University and Agent Skills consumers. It includes mission, source, failure pattern, recovery candidate and blockers; `skillPromotionAuthorized:false`.
3. **INDEPENDENT_VERITAS:** Existing authorized runtime Veritas authenticates PRE/POST and same-request real execution evidence at the exact capability boundary. Documentation cannot manufacture this.
4. **CANONICAL_RECEIPT + LEARNING:** Existing Receipt Ledger writer/readback then qualified Learning Ledger writer/readback admit the real same-request outcome. Only independently eligible evidence may promote institutional capability, skill mastery, or task completion.
5. **CONTINUITY:** Once qualified, index the lesson in the existing University/Skills authority and carry supersession, contradiction, source version and regression scope. Never erase a verified failure by rewriting history.

Each subsequent change requires **its own new checkpoint/updated evidence**. Do not reuse this 2026-10-27 source-only test count to certify a later commit, runtime provider, device or request. The repository's checkpoint checker scans every JSON checkpoint in `docs/checkpoints/` (currently two separate C3 source experiences), retaining their distinct evidence and source commits; it is **not yet a cross-repository production gate**. Real admission delegates to the existing [Standards PR #24 checkpoint evaluator](https://github.com/4citeB4U/LeeWay-Standards/pull/24), through the bounded [Standards handoff](STANDARDS-ENGINEERING-HANDOFF.md), once that upstream draft and its authenticated runtime binding are qualified.
