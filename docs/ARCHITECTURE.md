# Experiential Memory and Growth: design contract v0

## The experience arc

`ACTOR → CONTEXT → INTENDED ACTION → OBSERVATION → SURPRISE/FRICTION → FEEDBACK → HYPOTHESIS → INDEPENDENT CHECK → GOVERNED LESSON → RETRIEVAL → ADAPTATION → NEW EVIDENCE`

Not knowing is a first-class state. `UNKNOWN`, `TENTATIVE`, `CONTRADICTED`, `USER_CORRECTED`, `VERIFIED_WITHIN_SCOPE` and `UNVERIFIED` are not defects to be hidden. Failed execution, invalid assumptions, changed preference and user correction are meaningful experiences.

## Two trust lanes

**Experiential candidate lane:** Owner-authorized private capture → encrypted append journal → integrity check → tentative time/preference projection → user correction or approval → constrained RAG retrieval. These are not canonical operational lessons and cannot authorize actions.

**Governed operational lane (existing):** Runtime Fabric → independent Veritas PRE → Harness/Formula/Dispatcher → real capability execution → independent Veritas POST → canonical Receipt Ledger → canonical learning writer/readback → Agent University index. This repository must bind to the existing authentic provider once qualified, never issue its own fake PASS or bypass C3.

## Privacy and interpretation

- Consent to collect **is separate** from consent to personalize; both are separate from consent to proactively act or send notices.
- User preferences can be explicitly supplied; inferred patterns stay tentative and reversible. Silence is not proof of sleeping, dietary preferences or emotion.
- Do not infer mental health, cognitive impairment, stress or fatigue from fragmented speech. Use observable conversational preferences or ask for clarification when needed.
- Personal events should be owner-scoped, private, encrypted and removable through a deliberate privacy workflow. GitHub hosts source only.
- Opt-out and user correction must stop the relevant projection immediately. Retention, export and deletion controls require separate implementation before production.
- Inference samples should be counted across distinct calendar days, with negative evidence and changing preferences considered before promotion. Three days is **not** a clinical, behavioral or permanent pattern guarantee.

## University consumers

Expose stable read-only projection interfaces for Agent University, Agent Skills, Digital Brain and Machine Consciousness. All outputs need classification, source event IDs, evidence scope, timestamps and freshness; RAG retrieval must not turn a hypothesis into user fact. Shared learning is permitted only for appropriately de-identified, owner-authorized transferable procedural patterns, not cross-user personal habits.

## Resilience and recovery

Candidate journal uses AES-256-GCM and hash-chain verification with fsynced append; exclusive `.lock` prevents concurrent writers while the lock exists. It does not automatically clear stale locks or incomplete tails. Post-crash uncertainty requires an authorized reconciliation path, not blind cleanup. Multi-host replication, key rotation, secure erasure, backup/restore and disk-full testing are future gates.

## Admission and next gate

The existing C3 provider accepts production learning only after real request-correlated independent Veritas and canonical Receipt Ledger proof. The next production step is read-only custody verification and qualified binding, followed by a controlled exact same-request write/restart/readback test. Initial source tests here qualify **only** the candidate subsystem, not deployment, autonomy or persistent personal companionship.
